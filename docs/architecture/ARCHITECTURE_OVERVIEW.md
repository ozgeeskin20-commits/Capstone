## Decision process

Create a uniquely numbered ADR from [ADR-000-TEMPLATE.md](decisions/ADR-000-TEMPLATE.md) for each architectural decision. Record context, drivers, alternatives, decision, consequences, implications, risks, status, approval evidence, related requirements and actual GitHub Issues. Allowed statuses are Draft, Proposed, Accepted, Rejected and Superseded. Mark a decision Accepted only after explicit project-owner approval; record the acceptance date and evidence. If there is no approval or related issue, state that it is pending or none exists rather than inventing one.

Preserve decision history. An Accepted ADR becomes Superseded only when its replacement is Accepted; both records must reference each other. Do not implement unapproved architectural changes. No project-specific ADR has been created yet. The team-reported external Colab prototype is not a selected production architecture and is not integrated here; see [data sources](../DATA_SOURCES.md).
