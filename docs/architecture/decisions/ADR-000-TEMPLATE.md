# ADR-000: Template — replace with a unique ADR identifier and title

This is a template, not a project decision. Use a new unique identifier for each decision.

- **Status:** Draft / Proposed / Accepted / Rejected / Superseded
- **Date proposed:** Pending until proposed.
- **Date accepted:** Pending until explicitly approved by the project owner.
- **Decision owner:** Identify the owner or state unassigned.
- **Related requirements:** List applicable `REQ-NNN` identifiers or state none identified.
- **Related ADRs:** List applicable ADR identifiers or state none identified.
- **Related GitHub Issues:** Link actual issues or state none exists.
- **Approval evidence:** Record explicit project-owner approval and its source, or pending.
- **Supersession references:** Identify the replacement or prior ADR where applicable, otherwise none.

## Lifecycle

- **Draft:** Initial working document.
- **Proposed:** Ready for review.
- **Accepted:** Explicitly approved by the project owner.
- **Rejected:** Reviewed and not accepted.
- **Superseded:** Replaced by a subsequently Accepted ADR. An Accepted ADR may become Superseded only when its replacement is Accepted; both records must reference each other.

## Context and problem statement

Describe the problem, constraints and evidence.

## Decision drivers

Describe the requirements and factors guiding the choice.

## Alternatives considered

Describe feasible alternatives and their consequences.

## Decision and rationale

Describe the decision, its scope and technical rationale.

## Positive consequences

Describe expected benefits.

## Negative consequences and trade-offs

Describe costs, compromises and adverse effects.

## Security, privacy, operational and maintenance implications

Describe relevant implications or state that none has been identified.

## Risks

Describe risks, mitigations and links to the risk register where applicable.

## Implementation implications

Describe implementation effects and dependencies without authorizing unapproved implementation.

## History

Record status changes, approval evidence and any superseding ADR. Never mark Accepted without explicit project-owner approval.
